# 운전 습관 코치 — 서비스 기획안

작성일: 2026-10-28 · 버전: 0.2 · 상태: 사용자 검토용 기획 초안

구현 현황: [온유 드라이브 MVP 작업 보고서](implementation-report.md). 아래는 기획 기준이며 실제 구현·검증 범위는 보고서에 구분했습니다.

> 운전 중에는 점수로 간단히 확인하고, 도착 후에는 내 습관이 차량과 탑승자에게 미치는 영향을 이해한다. 장기적으로는 축적한 주행·체감 데이터를 자동주행의 승차감 평가와 개선에 활용한다.

## 1. 기획 배경과 대상

운전자는 자신의 행동이 차량과 동승자에게 어떤 영향을 줄 수 있는지 알기 어렵다. 운전 경력이 길어도 익숙한 행동을 돌아볼 기회가 적으며, 급가감속 횟수나 종합 점수만으로는 개선할 이유와 방법을 이해하기 어렵다는 문제 가설에서 출발한다. 실제 수요와 기존 서비스 대비 차별성은 사용자 인터뷰와 경쟁 서비스 조사로 검증한다.

대상은 초보운전자를 포함한 모든 운전자다. 첫 사용 상황은 일상적인 출퇴근과 가족 이동으로 설정한다. 어린이·노약자 등 배려가 필요한 동승자와 이동하는 경우 더 엄격한 부드러움 기준을 선택할 수 있다. 동승자의 나이가 실제 민감도나 건강 상태를 결정한다고 가정하지 않는다.

서비스가 제공할 가치는 세 가지다.

- **발견:** 자신도 모르고 반복하는 운전 행동을 확인한다.
- **이해:** 그 행동이 차량 관리와 동승자의 편안함에 어떤 관련이 있는지 배운다.
- **개선:** 좋은 행동에 대한 보상과 주행 후 안내를 통해 습관 변화를 확인한다.

## 2. 핵심 서비스 구조

**출발 전 모드 선택 → 주행 중 점수·무음 알림 확인 → 드라이브별 이벤트 자동 기록 → 주차 후 드라이브 상세에서 원인·영향 복기 → 다음 주행에서 개선 확인**

| 시점 | 사용자 경험 | 서비스 역할 |
|---|---|---|
| 출발 전 | 일반 / 어린이 동승 / 노약자 동승 중 선택 | 해당 주행의 평가 모드와 기준 설명 |
| 주행 중 | 대표 점수와 현재 모드, 짧은 무음 알림 확인 | 가점·감점 반영, 해당 드라이브에 이벤트 자동 기록 |
| 도착 후 | 드라이브 상세에서 점수 변화와 반복 습관 확인 | 이벤트 타임라인, 관찰 사실, 점수 요인, 영향 설명, 개선 행동 제공 |
| 다음 주행 이후 | 같은 습관이 줄었는지 확인 | 조건이 비슷한 주행의 경향과 변화 안내 |

사용자가 주행 중 메모할 필요는 없다. 상세 리포트는 주행 종료 후 안전하게 주차된 상태에서 확인한다. 점수는 참고 정보이며 운전에 필요한 제동이나 조작보다 우선하지 않는다.

## 3. 점수의 의미와 기본 원칙

대표 점수는 **관찰된 운전 행동을 서비스의 기준으로 평가한 운전 습관 점수**다. 실제 차량 건강, 부품 잔여 수명, 사고 확률, 동승자가 느끼는 편안함의 확률을 뜻하지 않는다.

내부 평가에서는 차량 관리 관점과 주행 부드러움 관점을 구분한다. 화면에는 대표 점수를 표시하되, 상세 내역에서는 어떤 기준이 반영됐는지 설명한다. 최종 결합 방식과 항목별 수치는 검토·검증 대상이다.

### 가점과 감점 — 초기 제안

- 급가속·강한 감속 등 평가 대상 행동은 감점 후보로 기록한다.
- 부드러운 출발·완만한 정차·일정 구간 동안 이어지는 부드러운 주행은 가점 후보로 기록한다.
- 한 번의 행동 기록과 여러 주행에서 반복된 습관 판정을 분리한다.
- 점수는 회복돼도 이전 행동과 점수 변화 기록은 삭제하지 않는다.
- 강한 감속을 곧바로 운전자의 잘못이나 실제 브레이크 패드 마모로 판정하지 않는다.

**검토용 시작안:** 매 주행 100점에서 출발하고 0~100점 사이에서 가감한다. 좋은 행동으로 잃은 점수를 회복할 수 있다. 100점에서의 좋은 행동도 칭찬 기록에 남기며, 가산점을 비축해 이후 감점을 상쇄하지 않는다. 시작부터 점수가 오르는 경험이 필요하다면 시작값을 조정하는 대안을 다음 검토에서 비교한다.

### 점수 변화 예시

아래 수치는 화면 흐름을 설명하기 위한 가상 값이다. 감지 임계값이나 실차 검증 결과가 아니다.

| 이벤트 | 일반 모드 | 동승 배려 모드 | 설명 |
|---|---:|---:|---|
| 평가 가능한 강한 감속 | -4 | -6 | 차량 관련 -2는 동일, 부드러움 관련 -2를 배려 모드에서 -4로 확대하는 예시 |
| 평가 가능한 급출발 | -3 | -5 | 차량 관련 -1은 동일, 부드러움 관련 -2를 -4로 확대하는 예시 |
| 부드러운 주행 구간 유지 | +1 | +1 | 회복 상한·적용 간격을 두고 반복 적립 방지 |
| 원인이나 신호가 불명확한 이벤트 | 보류 | 보류 | 점수에는 반영하지 않고 참고 기록으로 분리 |

동승 배려 모드는 부드러움 기준의 가중치를 높이는 설정이다. 같은 행동이 어린이 동승 때문에 차량을 더 마모시킨다고 해석하지 않는다. 어린이·노약자 모드는 선택하기 쉬운 프리셋이며, 세부 민감도 개인화는 후속 범위로 둔다.

### 점수 왜곡 방지

- 가속도와 그 변화율이 같은 제동을 가리키는 경우, 중복 감점하지 않도록 이벤트를 묶는다.
- 가점을 얻기 위해 출발·정차를 반복하는 행동을 유도하지 않도록 구간 단위 보상과 회복 한도를 검토한다.
- 필요한 급제동을 피하도록 유도하지 않는다. 긴급 상황 여부를 판단할 근거가 없으면 단정적인 잘못 표시를 하지 않고, 점수 반영 보류 또는 평가 제외 기준을 적용한다.
- 긴 주행이 불리해지는 문제를 검증한다. 장기 추세는 단순 최종 점수 대신 거리·시간당 이벤트와 도로 조건을 함께 검토한다.
- 다른 모드나 다른 점수 규칙 버전의 결과를 그대로 비교하지 않는다. 모드와 규칙 버전을 기록한다.
- 결측·지연·노이즈 등 데이터 품질이 낮은 구간은 평가에서 제외하고 평가 가능 범위를 표시한다.

## 4. 기능 후보와 첫 시연 범위

| 기능 | 우선순위 | 확인할 조건 |
|---|---|---|
| 급가속·강한 감속 기록 | 첫 시연 후보 | 속도·가속도 신호, 갱신 주기와 품질 |
| 부드러운 출발·정차 가점 | 첫 시연 후보 | 연속 신호와 구간 판정 가능성 |
| 일반·어린이·노약자 동승 모드 | 첫 시연 후보 | 주차 상태에서 선택, 가중치 설명 |
| 대표 점수와 변화 이력 | 첫 시연 후보 | 주행 중 UI 허용 범위와 제한 연동 |
| 차량 영향 설명과 개선 카드 | 첫 시연 후보 | 차량 유형에 맞는 검증된 설명 |
| 반복 습관 요약 | 첫 시연 후보 | 여러 주행의 기록; 시연에서는 재생 데이터 표시 |
| 정차 중 큰 조향 습관 | 후속 검증 후보 | 속도·조향 데이터 및 차종별 설명 근거 |
| 커브·차선 변경의 부드러움 | 후속 검증 후보 | 횡방향 움직임·상황 정보; 조향만으로 차선 변경 확정 금지 |
| 방지턱 통과 습관 | 후속 검증 후보 | 방지턱 위치·수직 충격 또는 신뢰할 수 있는 대체 정보 |
| 제한속도 구간의 감속 습관 | 후속 검증 후보 | 현재 도로에 맞는 제한속도와 위치 정합성 |

차량 데이터로 감지한 행동과 차량 관리 설명을 구분한다. 속도 감소만으로 브레이크 페달 사용이나 마찰 브레이크 사용량을 확정하지 않는다. 방지턱·제한속도 정보가 없으면 해당 기능을 지원한다고 표시하지 않는다.

## 5. 화면과 리포트

### 출발 전

현재 모드와 점수 기준을 확인한다. 모드 변경과 자세한 설명은 주차 상태에서 제공한다. 동승자의 실명·생년월일·의료 정보를 입력받지 않는 구성을 우선한다.

### 주행 중

대표 점수와 모드를 표시하고, 점수 변화가 발생하면 고정된 안내 영역에 원인과 변화량을 짧게 무음으로 표기한다. 예시는 `강한 감속 · -4`, `부드러운 주행 · +1`이다. 평가가 보류된 이벤트에는 감점됐다는 알림을 표시하지 않는다.

알림은 소리·진동·반복 점멸 없이 자동으로 사라지며, 확인이나 닫기 조작을 요구하지 않는다. 연속 이벤트는 화면에 알림을 쌓지 않고 최신 안내로 묶되, 개별 기록은 모두 보존한다. 자세한 표시 시간과 빈도는 시선 분산과 플랫폼 정책 검토 후 확정한다. 시선과 조작을 요구하는 미션이나 실시간 순위 경쟁은 제공하지 않는다.

점수 변경과 원인은 해당 드라이브에 자동 저장한다. 알림을 놓쳐도 기록이 남는다. 주행 중 알림을 눌러 상세 화면을 열도록 유도하지 않으며, 드라이브·이벤트 상세는 안전하게 주차한 상태에서 제공한다. 신호 대기와 같은 일시 정차만으로 상세 화면을 허용하지 않는다.

Pleos 공식 가이드는 간결한 정보, 최소한의 상호작용, 주행 제한 상태에 따른 기능 축소를 요구한다. 이 원칙에 맞춰 설계하되, 점수 화면의 주행 중 사용 허용은 앱 분류와 심사 조건을 추가 확인한다. 제한되는 경우 해당 화면을 숨기고 기록·사후 리포트 흐름을 제공한다. [Pleos 주행 안전 설계 가이드](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)

### 주행 후

기록은 `드라이브 목록 → 드라이브 상세 → 이벤트 상세`로 탐색한다. 드라이브 목록에는 주행 일시·시간·최종 점수·모드를 보여준다. 드라이브 상세의 첫 화면에는 최종 점수, 평가 모드, 주요 가점·감점 이유, 오늘의 개선 행동 하나를 보여준다. 총 감점과 회복 점수를 분리해 최종 점수가 이전 이벤트를 가리지 않도록 한다.

드라이브 상세에는 점수 변화 그래프와 시간순 이벤트 목록을 연결해 제공한다. 이벤트마다 발생 시각, 행동, 변화량, 변경 전후 점수, 적용 기준을 확인할 수 있다. 한 행동에 여러 평가 요인이 적용됐다면 합계와 항목별 내역을 함께 표시한다. 예를 들어 가상의 `96 → 90점` 변화에는 `차량 관리 기준 -2 / 기본 부드러움 기준 -2 / 동승 배려 가중치 추가 -2`처럼 합계가 맞는 근거를 제공한다. 이 값들은 검증 전 시연 예시다.

가점·감점·평가 보류를 구분해 볼 수 있으며, 알림을 표시하지 못했거나 사용자가 보지 않은 이벤트도 기록에서 확인할 수 있다. 점수 상한에서 감지한 좋은 행동은 `부드러운 주행 · 100점 유지`로 기록해 실제 점수 증가와 구분한다.

**가상 리포트 예시**

> 이번 주행: 91점 · 어린이 동승 모드  
> 감점 12점 / 회복 3점  
> 좋은 변화: 후반 구간에서 완만한 정차가 이어졌어요.  
> 돌아볼 습관: 최근 주행에서 강한 감속이 반복해서 관찰됐어요.  
> 다음 주행 제안: 여유 있게 감속할 수 있었던 상황인지 돌아보세요.

드라이브 상세에서 각 이벤트를 열면 아래 내용을 제공한다.

1. **관찰:** 언제 어떤 움직임이 감지됐는가?
2. **점수 근거:** 변경 전후 점수는 얼마이며, 어느 평가 기준·동승 모드·가중치가 각각 얼마나 반영됐는가?
3. **차량 영향:** 해당 행동이 어떤 사용·관리 특성과 관련될 수 있는가?
4. **탑승자 영향:** 어떤 흔들림으로 느껴질 수 있는가?
5. **개선:** 다음 주행에서 실천할 행동은 무엇인가?

차량 영향 설명은 검증한 자료와 차량 유형에 맞춘다. 예를 들어 반복적인 강한 마찰 제동은 열과 마모에 영향을 줄 수 있지만, 전기차·하이브리드는 회생제동을 구분해야 하며 해당 이벤트의 실제 마모량으로 환산하지 않는다. ## 6. 축적할 데이터와 활용 목적

원시 데이터가 모두 제공된다고 전제하지 않고, 접근 가능한 신호와 동의 범위를 확인한 뒤 수집 항목을 확정한다.

| 데이터 | 수집·생성 목적 | 설계 원칙 |
|---|---|---|
| 주행·이벤트 식별자와 시간 | 점수 변화 재현과 주행 복기 | 시각 동기화 및 데이터 누락 표시 |
| 접근 가능한 속도·가속도 등 | 움직임과 이벤트 판정 | 신호 출처·품질·갱신 간격 기록 |
| 모드·가중치·점수 규칙 버전 | 평가 이유와 조건 설명 | 설정 변경 전후 결과를 구분 |
| 이벤트 전후의 짧은 구간 | 단일 순간을 넘어 맥락 복기 | 필요한 범위만 저장, 보관 기간 결정 필요 |
| 동승자의 선택적 사후 체감 | 부드러움 지표와 실제 느낌 비교 | 별도 입력 주체와 동의, 미입력은 미상으로 처리 |
| 운전 주체·개입 여부 | 장기적으로 사람·자동주행 구간 구분 | 신뢰할 수 있는 출처가 없으면 미상으로 기록 |
| 차종·주행 조건 | 서로 다른 차량·도로 조건의 혼동 감소 | 확보 가능한 항목만 사용 |

내부 점수는 정답 데이터가 아니다. 서비스가 만든 점수만으로 자동주행의 편안함을 학습·검증하면 같은 평가 규칙을 반복하는 데 그칠 수 있다. 독립적인 동승자 체감과 조건 정보를 함께 확보하는 것이 확장의 핵심이다.

현재 운전자의 성찰용 기록과 향후 공동 연구용 활용은 목적을 구분한다. 외부 공유와 모델 연구 활용은 별도 동의·협약을 전제로 하고, 기록 열람·삭제와 보관 기간 설정 방안을 설계한다. 원시 위치·주행 정보는 식별 위험을 검토하며, 집계만으로 충분한 목적에는 상세 위치를 사용하지 않는다.

## 7. 핵심 확장 전략 — AI·자동주행(FSD 등)의 승차감 평가와 개선

### 기획안에 포함할 확장 메시지

> 이 서비스는 사람이 운전하는 동안 반복적인 운전 습관을 이해하고 개선하도록 돕는다. 향후 AI 기반 자동주행이 확대되면, 축적된 주행 특성과 동승자 체감 데이터를 활용해 어떤 출발·감속·정차·방향 전환이 더 편안하게 받아들여지는지 분석한다. 이를 통해 운전 주체와 관계없이 탑승자 관점에서 이동 경험을 평가하고, 검증된 결과를 자동주행 시스템의 승차감 개선을 위한 평가 자료로 발전시키는 것을 목표로 한다.

여기서 FSD는 사용자가 제시한 미래 확장 사례다. 특정 제품의 자율성 수준, 현재 연동 가능성, 개발 로드맵을 주장하지 않는다.

### 데이터가 개선으로 이어지는 경로

1. **주행 특성과 체감 연결:** 가감속과 움직임의 변화, 동승 모드, 가능하면 도로·차량 조건을 사후 체감과 연결한다. 동승자 직접 응답과 운전자의 추측을 구분한다.
2. **편안한 패턴의 가설 도출:** 예를 들어 같은 속도 변화에서도 감속이 시작되는 시점과 감속의 변화가 체감에 어떤 차이를 만드는지 살펴본다. 관찰 관계를 인과 효과로 단정하지 않는다.
3. **사람 운전과 자동주행 구간 구분:** 신뢰할 수 있는 운전 주체·모드 전환·운전자 개입 정보가 있는 구간만 구분해 평가한다. 전체 주행을 한 운전 주체의 결과로 묶지 않는다.
4. **조건을 맞춘 평가:** 차종, 속도, 도로, 교통, 탑승 조건 등 확보 가능한 요인을 맞추고, 별도 검증 데이터로 승차감 평가 기준을 점검한다. 같은 사람의 기록이 학습과 평가에 섞이지 않도록 설계한다.
5. **협력사 검증으로 확장:** 동의받은 데이터와 평가 방법을 바탕으로 시뮬레이션·통제된 시험에서 대안을 비교한다. 실제 주행 계획 개선은 차량 제어 권한과 안전 검증 체계를 가진 협력사가 수행하는 단계다.

이 앱이 자동주행 소프트웨어를 직접 수정하거나 안전 판단을 대신하지는 않는다. 승차감 개선은 안전 제약을 충족한 대안들 사이에서 검증한다. 초기 데이터만으로 실제 차량 수명 연장이나 승차감 개선 효과를 보장하지 않는다.

### 단계별 발전

| 단계 | 제공 가치 | 진입 조건 |
|---|---|---|
| 1. 운전 습관 코치 | 점수·원인·차량 영향 설명과 습관 개선 | 차량 내 데이터 접근과 평가 기준 검증 |
| 2. 개인화된 동승자 배려 | 모드별 경향과 체감 피드백 반영 | 충분한 응답과 개인화 효과 검증 |
| 3. 자동주행 승차감 평가 | 운전 주체별 주행 특성과 체감 비교 | 신뢰할 수 있는 모드 정보와 제휴 |
| 4. 개선 검증 지원 | 더 편안한 주행 패턴의 시험·평가 자료 제공 | 별도 동의, 협력사 연계와 안전 검증 |

## 8. 공모전 시연 제안

**시연 목표:** 같은 주행 행동이 모드에 따라 어떻게 평가되고, 좋은 행동으로 점수가 회복되며, 사후 설명이 다음 행동으로 이어지는지 보여준다.

1. 주차 상태에서 일반 모드를 선택하고 점수의 의미를 확인한다.
2. 동일한 재생 시나리오로 급출발·강한 감속·부드러운 주행에 따른 점수 변화와 짧은 무음 알림을 보여준다.
3. 어린이 동승 모드의 별도 재생으로 부드러움 관련 감점 가중치 차이를 보여준다.
4. 안전하게 주차한 상태의 드라이브 상세에서 점수 변화 그래프와 이벤트 목록을 확인하고, 한 이벤트를 열어 증감 요인과 동승 가중치 내역을 보여준다. 여러 주행에서 반복된 습관도 확인한다.
5. 실제 체감 피드백을 연결하면 향후 자동주행 평가로 어떻게 확장되는지 한 장면으로 설명한다.

SDK로 검증한 기능, 재생한 신호, 가상 동승자 응답을 명확히 구분한다. 재생 데이터를 실차에서 수집한 데이터로 소개하지 않는다. 위험 행동을 실제 도로에서 만들어 촬영하지 않는다.

공모전은 차량 특화성·창의성·기술 활용성·사업성을 평가하고, 개발 산출물 제출에 가산점을 부여한다. 본 기획은 차량 데이터가 만드는 사후 학습과 동승 모드의 의미를 시연의 중심에 둔다. [공식 모집 공고](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000001)

## 9. 검증할 가치와 사업 가설

- 사용자가 점수 변화의 이유를 이해하고 자신의 반복 습관을 설명할 수 있는가?
- 가점과 회복이 점수 확인에 대한 집착보다 재사용과 개선 동기로 이어지는가?
- 같은 조건에서 비교했을 때 목표 습관의 빈도가 변하는가? 도로 조건 변화와 혼동하지 않는가?
- 부드러움 지표와 동승자 직접 피드백 사이에 일관된 관계가 있는가?
- 주행 중 화면과 점수 변화가 시선 분산이나 불필요한 조작을 유발하지 않는가?

초기 사업 가설은 개인 운전자의 습관 코치다. 고급 추세·개인화 기능, 동의 기반 차량 운영 교육, 협력사의 승차감 평가 도구는 후속 검증 후보로 둔다. 수익과 효과를 검증 전 확정하지 않으며, 보험료 산정·운전자 서열화·차량 정비 진단은 첫 기획 범위에 포함하지 않는다.

## 10. 다음 결정과 기술 확인

공식 문서 조사에서는 속도의 AAOS 접근 경로와 브레이크 페달 상태·조향각의 SDK 조회·구독 API를 확인했다. 다만 로컬 가속도 접근, 실차 권한, 갱신 주기와 감지 정확도는 아직 검증하지 않았다. 별도의 Cloud Vehicle Data API에 가속도 필드가 있다는 사실을 차량 내 실시간 지원의 근거로 사용하지 않는다. [공식 속도 FAQ](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq), [Brake API](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/brake/entry), [SteeringWheel API](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/steering-wheel/entry)

주행 중 점수 표시는 운전 집중을 고려한 앱 선언과 플랫폼 제한 준수가 필요하며, 해당 화면의 허용 여부는 추가 확인해야 한다. 세부 근거와 검증 항목은 [Pleos 기술 가능성 조사](research/pleos-feasibility.md)에 정리했다.

현재까지 확정된 것은 서비스 방향이다. 아래 세부 사항은 초안 제안이며 사용자 검토와 기술 확인을 거쳐 결정한다.

1. **데이터 가능성:** 차량 내 SDK 권한, 차종 지원, 갱신 주기, 신호 품질 및 주행 중 UI 범위. Cloud Vehicle Data API의 데이터 항목을 차량 내 실시간 지원으로 간주하지 않는다.
2. **점수 규칙:** 시작값·상한·회복 간격·동승 가중치·판단 보류 기준과 주행 길이 보정.
3. **시연 범위:** 실제 지원 가능한 행동, 화면 수, 재생 데이터와 실제 SDK 연동의 경계.

단계마다 조사 결과와 선택지를 사용자에게 보여주고 피드백을 받아 구체화한다. [결정 지도](../.scratch/driving-habit-coach/map.md)
